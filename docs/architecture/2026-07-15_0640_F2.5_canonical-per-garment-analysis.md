## 1. Seam design

Two layers, cleanly separated:

### 1.1 `colorlab/segmentation.py` — the mask contract (no inference)

- **Class ids** = MediaPipe Selfie Multiclass (D21), mirror of the Dart
  constants, do not renumber: `0 background · 1 hair · 2 body-skin ·
  3 face-skin · 4 clothes · 5 others` (`NUM_CLASSES = 6`, `MODEL_SIDE = 256`).
- **Dart-parity pre/post helpers** (pure numpy, unit-tested):
  `preprocess_rgb` (bilinear, center-aligned `src = (dst+0.5)·scale − 0.5`
  clamped at 0, [0,1] normalize), `class_map_from_scores` (argmax, ties → 
  lowest index like Dart's strict `>`), `upscale_class_map` (nearest,
  `my = y·256 // h` — same integer arithmetic, same blockiness).
- **`split_garment_masks(class_map)`** — clothes-bbox mid-row split into
  `upper`/`lower` (v1 geometric split, D21) **plus the two v1 hygiene guards
  the spike flagged**:
  - `MASK_ERODE_PX = 2`: each REGION mask eroded 2 px before sampling
    (the 256→full-res edges bleed boundary colors; eroding per region also
    trims the upper/lower seam so hem-transition pixels vote in neither).
  - `MIN_REGION_FRACTION = 0.005`: a post-erosion region under 0.5% of the
    frame is absent (chest-up framing ⇒ no `lower` palette from a waistband
    sliver).
- **Loud degrade**: `NoPersonError` when clothes coverage <
  `MIN_CLOTHES_COVERAGE = 0.01` (mirror of Dart `isNoPerson`) or when no
  region survives the guards. Callers fall back to `analyze_palette`.

### 1.2 `colorlab/pipeline.py` — `analyze_garments` (the algorithm layer)

```python
analyze_garments(img, class_mask, *, n_colors=GARMENT_COLORS) -> GarmentAnalysis
```

- Per garment: `dominant_colors` (the SAME K-means + LAB merge core) over the
  garment's pixels only; `GARMENT_COLORS = 3` (a garment is 1–2 colors plus
  shading; the whole-photo 5 over-fragments a solid garment).
- Per garment: `GarmentPalette(colors, weights, base_index, pixel_fraction)`
  — `base_index = pick_harmony_base_index` on the garment alone, `-1` = a
  fully neutral garment (per-garment canvas signal).
- Combined outfit palette: per-garment palettes **concatenated** with weights
  scaled by pixel share, sorted (sum ≤ 1, the `MIN_WEIGHT` convention).
  Deliberately NOT re-merged across garments so every swatch keeps its
  attribution: `swatch_regions[i]` names the owning garment. Cross-garment
  display dedupe (monochrome outfits showing two near-identical pinks) is a
  display-layer decision for the UX round.
- Outfit base = **decision #6 lifted to the outfit level**:
  `pick_harmony_base_index` on the combined palette — the most chromatically
  prominent garment color wins, never a neutral; `base_index = -1` ⇒ canvas
  mode (D10), `base_region` names the winning garment otherwise.
- `analyze_palette` signature and body are UNTOUCHED. New pin test
  (`test_analyze_palette_legacy_core_path_is_pinned`) locks its exact output.

**Open calibration note (flagged, not decided):** `pick_harmony_base_index`
carries the #57 gate (`POP_ON_NEUTRAL_MIN = 0.10`: tiny chromatic patch on a
neutral-dominant outfit → demoted). With a mask, that patch is KNOWN to be
garment (a red logo on a black hoodie), so the gate may now demote genuine
accents. Kept as-is for consistency with the canonical base rule; revisit with
real-photo evidence on the D23 eval set.

writes one contract PNG per photo + a coverage summary line.

## 3. Mask-format contract (agreed hand-off with QA)

**Grayscale 8-bit PNG (mode `L`), same width/height as the photo, pixel VALUE
= class id 0..5.** No palette, no 0-255 scaling (a viewer shows it
near-black — expected). Suggested naming: `<photo_stem>.mask.png` next to the
photo. `load_class_mask` validates loudly: RGB PNGs and scaled/visualization
masks (values ≥ 6) are rejected, never silently misattributed. QA's
`segmentation_battery` landed against this same format in parallel (their
suite passes on this layer unmodified).

## 6. What the NEXT round (Dart parity) needs

1. **Port the algorithm layer to Dart** (`app/lib/core/color_engine/`):
   `splitGarmentMasks` guards (erode 2 px + min-region 0.5%) on top of the
   existing `MediaPipeGarmentSegmenter.buildMasks`, `GARMENT_COLORS = 3`
   per-garment K-means via the existing engine, combined palette + base
   across garments with the same conventions (`swatch_regions`, `base_index
   -1` = canvas). Erosion has no cv2 in Dart — a 5×5 min-filter over the
   bitmask is ~15 lines; keep the kernel SQUARE to match cv2.
2. **Golden fixtures**: generate per-garment fixtures from the canonical
   Python (synthetic photo + synthetic class map — model-free, so fixtures
   stay deterministic and CI-safe), byte-compared by the Dart suite like the
   existing outfit/product fixtures.
3. **Result-screen per-garment UX spec** (ux-designer, in progress) decides
   the display questions deliberately left out of the engine: cross-garment
   swatch dedupe, per-garment labels, D31-A neutral snap per garment.
4. **D23 eval set + QA battery** measure the layer on real photos (the gate
   G2.5 evidence); the #57-gate calibration note (§1.2) gets decided there.
5. CLI/`render_panel` per-garment surface: optional, only if a human-visual
   QA loop wants panels before the app round.
