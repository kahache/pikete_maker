## 1. The design in one paragraph

The result screen keeps its exact skeleton — share canvas on top, ONE
"Combina con" section, the two CTAs in the thumb zone — and only the
**inside of the share canvas** changes: instead of one whole-photo band
stack, it shows **two labeled garment blocks (ARRIBA / ABAJO)**, each with
its own proportional color bands and mono hex/% index. There is still **one
base, one badge, one recommendation set**: the base is the most chromatic
color *across both garments* (rule #6, now region-aware) and the base line
gains one honest sentence of attribution ("Sale de tu parte de arriba").
Everything else — harmony selection, deep-link, canvas mode, story export —
is untouched. When segmentation can't deliver two garments, the screen
degrades **silently** to fewer blocks or to today's whole-photo layout:
same screen, same tone, zero error language.

## 2. Load-bearing decisions (the "why" — read before objecting in review)

| # | Decision | Rationale |
|---|---|---|
| U1 | **One screen, one base, ONE "Combina con"** — NOT a recommendation section per garment | D7 radical simplicity: two harmony sections double the text, halve the hierarchy, and force Dani to choose twice. The product's promise is "dime qué me pega", singular. The per-garment value shows up in the *palette* (clean, attributed colors), not in duplicated advice. |
| U2 | **Region labels are "ARRIBA" / "ABAJO", never garment types** ("tu camiseta", "tus pantalones") | v1 of the model emits *regions*, not garment classes (D21: geometric mid-split of one "clothes" class). Calling a hoodie "camiseta" or a skirt "pantalones" is a lie the user catches instantly. Honest words, `label` type style, tertiary color — they are structure, not content. |
| U3 | **Base attribution is one sentence in the existing base line**, not a badge on the garment block | Purple stays at its 2 doses (BASE badge + watermark). The bold hex row inside the owning block + the sentence "Sale de tu parte de arriba" is enough wayfinding; a second badge would start a badge war. |
| U4 | **Degrades are silent.** No "no pudimos separar tu ropa", no toast, no icon | The user never saw the feature fail because the user never ordered segmentation — they ordered a palette. Today's whole-photo result was good enough to ship an MVP on; presenting it can't be framed as failure. Shame-free degrade = render the layout the data supports. (Analytics DOES record it — §6.) |
| U5 | **Single-region result is labeled "TU ROPA"**, not "ARRIBA" | A lone "ARRIBA" block begs the question "¿y mi parte de abajo?" — it advertises the miss. "TU ROPA" is always true, still communicates the upgrade over whole-photo (skin/wall/hair are GONE from the swatches), and asks nothing. |
| U6 | **Headline = "Tu pikete"** (CEO decision, 2026-07-15) | CEO overrode the default on review: "Tu paleta" → "Tu pikete" (consistent with the D26/D27 slang voice). Same slot/typography; copy-only change. |
| U7 | **A fully-neutral garment gets a 3-word caption** ("neutro — combina con todo"), chromatic garments get none | Mixed outfits (black jeans + red hoodie) are the most common real case. Without the caption a nearly-monochrome ABAJO block reads as "the app saw nothing down here". Three words, `caption`/tertiary, no color, no icon. |

## 3. Anatomy (token-mapped, top to bottom)

Everything not listed here is **identical to the current result screen**
(`app/lib/features/result/result_screen.dart`, canonical mockup
`docs/design/mockups/result.html`).

### 3.1 Share canvas (F6 object — still one RepaintBoundary)

Container unchanged: `surface`, `radius.lg`, `border`, `shadow.sm`,
padding `xl xl lg`.

1. **Headline** — "Tu pikete" (CEO 2026-07-15; was "Tu paleta"), `type.display`, `textPrimary`.
2. **Meta** — "Fit de hoy · {fecha}", `type.caption`, `textTertiary`. Unchanged.
3. **Garment block × 2** (NEW, `GarmentBlock`):
   - **Region label row**: text "ARRIBA" / "ABAJO", `type.label` (11/14 · 700
     · uppercase · 0.08em), `textTertiary`. No chip background, no border —
     bare label (U2: structure, not content). If the garment is canvas-mode
     (`isCanvas`), append the neutral caption on the same line, right-aligned
     or after an interpunct: "neutro — combina con todo", `type.caption`,
     `textTertiary` (U7).
   - **Band stack**: same grammar as today's `_Palette`, with a smaller
     height budget: `totalHeight = 120` per garment (was 280 for the single
     stack), `minBandHeight = 10` (was 12), row gap `space.sm` (was md).
     Bands keep proportional-to-weight heights; weights are **per-garment**
     (each block sums to 100% — the mono index makes that self-evident).
     Hex/% index column unchanged (`type.dataMono`; base row hex in
     `textPrimary` w700, others `textSecondary`; % always `textTertiary`).
     The **base row lives in whichever block owns the global base** — bold
     hex there only.
   - **Block separator**: hairline `border` top on the second block, padding
     `space.lg` above/below. (Same divider grammar as the harmony rows.)
4. **Base line** (MODIFIED copy only): dot 28px + BASE badge
   (`accentTint` bg / `accent` text — purple dose 1 of 2) + description now
   carries attribution: bold "Tu color dominante." + regular
   "Sale de tu parte de {arriba|abajo}. Todo conjunta alrededor de él."
   Max 2 lines at 390px — verified in the mockup. In canvas mode (both
   garments neutral) the base line is hidden, exactly as today.
5. **Watermark** — unchanged (purple dose 2 of 2).

### 3.2 "Combina con" section — UNCHANGED

One section, 4 selectable harmony rows (#82 radio behavior, first
pre-selected), computed from the **global base** (§6 contract). Title
"Combina con", sub "Toca una y mira looks reales con esos colores."
`SchemeNameChip` selected state, `SwatchStrip`, chevron in `action` — all
as-is.

### 3.3 Canvas section (both garments neutral) — UNCHANGED

Global canvas mode (D10): "Tu look es un lienzo" + curated accent pops
(`CanvasAccentsWrap`, selectable per #82). The share canvas above it still
shows the two labeled neutral blocks (each with its "neutro" caption —
here it earns its keep twice).

### 3.4 CTAs — UNCHANGED

"Ver looks así" (primary) + "Súbela a tu story" (secondary), thumb zone,
`ctaHeight` 56 pill.

## 4. States matrix

| State | Trigger (engine) | Share canvas | Base line | Below the card |
|---|---|---|---|---|
| **S1 · Two garments, ≥1 chromatic** (happy path) | `SegmentedAnalysisResult` with upper+lower | 2 blocks ARRIBA/ABAJO; bold hex in the base-owning block; neutral caption on a fully-neutral block (U7) | BASE badge + attribution sentence | "Combina con" ×4 from global base |
| **S2 · Two garments, both neutral** | global canvas (D10) | 2 blocks, both with neutral caption | hidden | "Tu look es un lienzo" + pops |
| **S3 · Single region** | one region survives the min-region guard (waist-up framing, tiny lower, etc.) | 1 block labeled **TU ROPA** (U5), `totalHeight = 200` (single block earns more room) | BASE badge, **no attribution sentence** — today's copy verbatim | unchanged (harmonies or canvas from that garment) |
| **S4 · Whole-photo degrade** | `SegmentationException` (isNoPerson OR model failure) → engine reruns today's whole-photo pipeline | **today's screen, pixel-identical** (single 280px stack, no labels) | today's copy | unchanged |
| **S5 · Real failure** | whole-photo pipeline ALSO fails / no chromatic subject | — | — | E3/E4 ugly states, unchanged (`user-flows.md`) |

Degrade rules in prose: **no state adds error language, iconography, or a
retry prompt.** S3 and S4 must be indistinguishable in tone from S1 — the
only difference is how much the data allowed us to say. `isNoPerson` does
NOT route to E4 by itself: E4 keeps its existing trigger (whole-photo
pipeline finds no usable subject), because the whole-photo fallback often
still produces a decent palette on photos the segmenter rejects.

## 6. Contract notes for mobile-dev / engine (hand-off)

**Reuse verbatim** (already shared in `app/lib/widgets/result_blocks.dart`
or local to `result_screen.dart`): `_ShareCanvas` container, `BrandWatermark`,
`_HarmoniesSection` + `_HarmonyRow` + `SchemeNameChip` + `SwatchStrip`,
`_CanvasSection` + `CanvasAccentsWrap`, CTA block, `shortSpanishDate`, the
RepaintBoundary/F6 export path, the #82 selection state machine, analyzing
screen, E3/E4.

**Parameterize** (small changes):
- `_Palette` → accepts `totalHeight` (280 today / 200 single-region / 120
  per garment) and `minBandHeight`; otherwise unchanged.
- `_BaseLine` → accepts an optional attribution string.

**New** (one widget): `GarmentBlock` = region label row (+ optional neutral
caption) + parameterized `_Palette`. Pure composition, no new tokens.

**Engine-side contract the UI assumes** (flagging, not designing —
backend/ml own the math):
1. **Global base**: ONE base across garments, chosen by rule #6. Careful:
   `GarmentPalette.weight`s are normalized *per region*, so comparing
   `chroma × weight` across garments raw is biased toward the smaller
   region — the comparison needs each region's pixel share as a factor.
   The UI consumes: owning region + index within that garment's palette.
2. **One harmony set** computed from that global base (the current
   `SegmentedAnalysisResult` carries per-garment harmonies; the UI renders
   exactly one set — S1 shows the global-base harmonies, S3 the single
   garment's).
3. **Global canvas** only when EVERY surviving garment is canvas-mode.
4. Mask erosion (~2–3 px) + min-region guard before palettes, per spike §7.3
   — the min-region guard is what feeds S3.
5. Degrade telemetry (#4 seams): log `segmentation_degraded
   {reason: no_person | region_too_small | model_failed, to: single | whole}`
   and tag `result_viewed` with `layout: garments | single | whole`. The
   F&F beta needs this to size how often S3/S4 actually fire.

**Latency / #55 — confirmed, no new loading UI.** Worst measured ARM chain
(spike addendum): model load 184 ms + warm-up 683 ms + steady ≤637 ms ≈
1.4 s; + 2 per-region palette extractions (~300 ms each, r6 measurement) ≈
**~2.0 s worst case, comfortably inside the 3.5 s #55 minimum window**. The
analyzing screen's step 2 copy ("Separando la ropa del fondo") becomes
*literally true* with zero changes. If a future device ever exceeds the
window, the existing behavior (bar holds at 96% cap) already covers it.

## 7. What needs the CEO

1. **U1 — one global recommendation** (not one per garment). This is the
   biggest call in the spec; everything downstream assumes it.
2. **U2/U5 — labels**: "ARRIBA / ABAJO" and "TU ROPA" for single-region.
   Alternative slang ("TOP / BAJO"?) welcome — same slots, same styling.
3. **U4 — silent degrade** (no messaging when we fall back). Growth may
   want the opposite someday ("look what premium segmentation does");
   design position: never shame the free path.
4. **U6 — keep "Tu paleta"** as the headline, or rename (e.g. "Tu pikete").
5. Mockup frames as-is: `docs/design/mockups/2026-07-14_2355_F2.5_per-garment-result.html`.
