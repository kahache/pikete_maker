## Metodología

- **Camino A — DEMO (equivalente al motor Dart):** `load_image` → todos los
  píxeles (máscara completa, `drop_skin=False`; sin quitafondo, sin filtro de
  piel) → `dominant_colors(k=5)` → `pick_harmony_base` → `harmonies` →
  `render_panel`. Es exactamente `colorlab <foto> --no-bg --keep-skin`. La
  equivalencia con el motor Dart está garantizada por la suite de paridad con
  fixtures dorados (#32, `app/test/core/paridad_fixtures_test.dart`).
- **Camino B — pipeline completo:** `remove_background` (GrabCut; sin rembg
  por Python 3.14, como documenta CLAUDE.md) → filtro de piel adaptativo (#20)
  → mismo resto.
- **Entorno:** Mac, `.venv` Python 3.14, working tree limpio sobre `ca34813`.
  Script de QA sobre la API de colorlab (scratchpad de sesión, no
  commiteado). Evidencia: `outputs/selfies-eval/resultados.json` (paletas,
  pesos, saturaciones, logs y tiempos por selfie) + 8 paneles
  `outputs/selfies-eval/selfieNN_{demo,full}.png`.
- **Criterio (el de G0, aplicado por foto):** (a) la paleta "es el outfit" a
  ojo; (b) la base de armonías nunca es piel/fondo/neutro arbitrario;
  (c) además, para #33: ¿candidata a foto hero del demo?

**Lectura para Fase 2 (quitafondo on-device v1):** en selfies de espejo el
pipeline completo **no arregla los KO, los transforma**: los dos "base=piel"
pasan a "paleta colapsada de 1 neutro con base neutra". En los dos OK aporta
una mejora real pero marginal, a cambio de 3-9× más tiempo y disparando el
guardarraíl de piel en 2/4 fotos. El valor del quitafondo para este caso de
uso depende de resolver antes #29 (guardarraíl), #21 (modo lienzo) y #22
(neutros casi-negros); sin esos tres, quitar el fondo solo cambia el modo de
fallo. La decisión D15 de NO portar GrabCut al demo queda respaldada por
datos.

## Hallazgos

- **H1 (nuevo, afecta al motor del DEMO/Dart): outfit neutro → base de
  armonías = piel.** En el camino demo no hay filtro de piel, y el modo
  lienzo (#21/D10) NO cubre este caso: el cluster de piel es cromático
  (sat ~0,5), así que la paleta no es "toda neutra" y `pick_harmony_base` lo
  elige legítimamente. 2/4 selfies reales caen aquí. Mitigación demo:
  curación de fotos hero (H1 no se toca en Fase 1 por D15). Mitigación
  producto: filtro de piel on-device (Fase 2) o detector "sin prenda
  cromática" que active el modo lienzo también con piel presente. **Propongo
  issue nuevo con este repro** (selfie02/selfie03 + cualquier outfit
  blanco/negro/gris con piel visible).
- **H2 (caso real para #22):** denim navy oscuro → #1F1F24, sat 0,139, a
  0,04 de la frontera `NEUTRAL_SAT`. Un usuario diría "visto de azul marino";
  el motor dice "neutro". selfie03 sirve como foto de regresión cuando se
  aborde #22.
- **H3 (más evidencia para #29):** `MAX_SKIN_FRACTION` disparado en 2/4
  selfies normales (55 % y 82 %) → el filtro de piel se autodesactiva
  exactamente en el tipo de foto del caso de uso real. Coherente con el
  39,5 % de `BASE_ES_PIEL` de la batería-200.
- **H4 (coherente con #30):** pipeline completo 6,9–14,4 s en Mac (guardarraíl
  PRD: p95 < 6 s). El camino demo tarda 1,6–4,5 s en Python; **la cifra que
  importa a G1 (< 10 s) es la del motor Dart en un Android real y nadie la ha
  medido aún** — ver estrategia de tests (doc hermano de hoy).
