## The one finding that matters: **base = 18/18 correct**

In **every** DUDA and the single KO, the CEO wrote **"Base OK"**. The base — the
most-chromatic garment color that seeds the harmony (product decision #6) — is
correct in **100% of the auto-OK set**, on real, varied, in-the-wild photos.
This validates the chroma×weight base rule end-to-end: even when the background
dominates the frame by area (row 158: the pavement+sky swatch is 84% of the
palette), it is low-chroma and therefore never wins the base. The MVP color
engine (base + harmony) is sound.

## All residual error is ATTRIBUTION in the *displayed* swatches

None of the DUDA/KO verdicts is an extraction error. In each, one of the top-3
swatches shown to the user is not a garment. It splits into **three** buckets:

| Bucket | Count | Rows | Fixed by |
|---|---|---|---|
| **Background** (wall/floor) | 7 | 143, 154, 158, 161, 193, 199, 200 | #48 (Python ✅) / **#49 Dart port (in progress)** |
| **Hair** | 4 | 137\*, 164, 180, 194 | MediaPipe Selfie Multiclass — `hair` class (D21) |
| **Skin** (bare leg/arm) | ~1–2 | 137\* | MediaPipe — `body-skin`/`face-skin` (D21) |

\*Row 137 mixes hair + bare-leg skin.

**"Hair" is a new sub-class.** Prior analyses lumped attribution into
background vs skin; the CEO review isolates **hair** as its own recurring
contaminant (4 rows). The YCbCr skin proxy does not catch it. This is not a new
work front: **MediaPipe Selfie Multiclass (D21, already chosen) segments
background + hair + body-skin + face-skin + clothes in a single model** — the
three buckets collapse into one already-decided fix. Net effect: #56 further
**de-risks Phase 2.5** rather than opening new scope.

## "Mola como producto, no sé si algorítmicamente" (CEO, ×10 rows)

The CEO's recurring note is, in effect, a product decision that Phase 2.5 makes
moot. Today: base correct + a neutral-ish background swatch → the eye accepts
the palette as coherent, so it "works as a product". Algorithmically the swatch
is not a garment. There is no purity threshold to hand-tune — the resolution is
to **segment** (remove non-garment pixels before palette extraction), after
which the displayed palette is 100% garment. No heuristic decision required.
